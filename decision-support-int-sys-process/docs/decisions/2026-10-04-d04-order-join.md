# D-04: order → session join candidate (plan §12 P0 row 4; H02, Q7)

**Answer (probed):** `udp_conversions.idorder` is a numeric string of
13–14 digits, distinct per order on all pilots — consistent with Shopify's
numeric order id, not `order.name` (`#1234`) and not a GID.

**Decision:** The Phase 7 `order-session-map` tries both Shopify keys
(`order.id` primary candidate, `order.name` fallback) and records the
match rate per site. Until a read-only token exists (D-05), the match rate
is unknown and H02's order→session map is `partial` per the Q7 default
(below 80 % match would keep it `partial` even then). `udp_conversions`
remains the revenue truth inside the engine either way.
